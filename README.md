# SWYNEX-Network-Security-Analysis

Task 2 of the SWYNEX Technologies internship: a **defensive** analysis of network traffic captured in a controlled lab environment.

## Repository contents

| File | Purpose |
|---|---|
| `analyze_pcap.py` | Python standard-library analyzer for supported Ethernet `.pcap` / `.pcapng` captures |
| `make_sample_pcap.py` | Creates a synthetic capture without sending network traffic |
| `sample_lab_traffic.pcap` | 39 fabricated packets on private lab addresses |
| `sample_findings.md` | Example output for the synthetic capture |
| `REPORT.md` | Report template for your own authorised lab capture |
| `FINDINGS.md` | Working notes from the personal lab capture; verify remaining items before submission |
| `tests/test_analyze_pcap.py` | Regression tests using synthetic data |
| `.github/workflows/tests.yml` | Runs regression tests on pushes and pull requests |

## Scope and ethics

Analyse only traffic you generated yourself in your own lab or an approved sample capture. The repository sample is synthetic: it is generated by a script and is not evidence of real network activity. Never publish captures containing other people's traffic, credentials, cookies, tokens, or private information.

## Requirements

- Python 3.10 or later recommended
- No third-party Python packages required
- Wireshark recommended for manually verifying observations

## Run the analyzer

From the repository root:

```bash
python3 analyze_pcap.py path/to/your_capture.pcapng -o my_findings.md
```

Open the capture in Wireshark and verify observations before treating them as findings. A port number alone does not prove the application protocol or that sensitive data was exposed.

## Generate and analyse the synthetic sample

The generator writes `sample_lab_traffic.pcap` to the current directory:

```bash
python3 make_sample_pcap.py
python3 analyze_pcap.py sample_lab_traffic.pcap -o sample_findings.md
```

The sample intentionally includes fabricated examples that exercise several detection rules. It does not send packets or capture real network traffic.

## Run regression tests

```bash
python3 -m unittest discover -s tests -v
```

Tests use a temporary directory and synthetic data. GitHub Actions also runs them on pushes and pull requests.

## Checks implemented

| Check | Current heuristic |
|---|---|
| Cleartext protocol indicators | TCP payload on ports 21, 23, 25, 80, 110 or 143 |
| Possible cleartext credentials | Selected text patterns in TCP payloads |
| Possible TCP SYN scan | One source sends SYN-without-ACK packets to at least 15 distinct destination ports |
| ARP anomaly | An IPv4 address appears with multiple sender MAC addresses in ARP replies |
| High ICMP volume | At least 50 IPv4 ICMP packets from one source |
| Long DNS label | A DNS label longer than 40 characters in UDP traffic using port 53 |

## Limitations

- This is an educational parser, not a production-grade packet decoder.
- IPv4 over Ethernet is the primary decoded path; IPv6 and other link-layer types are not fully analysed.
- PCAPNG support is limited and unusual interface/link-type combinations may not be interpreted correctly.
- Fragmented IPv4 packets, malformed/truncated records, DNS compression and other protocol edge cases require more robust handling.
- Port-based protocol indicators do not confirm the application protocol or credential exposure. Long DNS labels, repeated SYNs and multiple ARP MACs are indicators, not proof of malicious activity.
- Always validate packet details and context in Wireshark. Record what was observed, what remains uncertain, and what was not tested.
